# 上游範本貢獻指南

> **版本**：v1.0.0  
> **最後更新**：2026-02-25  
> **適用對象**：所有使用本範本的下游專案開發人員  
> **上游範本**：[99.spec-kit-cross-platform-template](https://github.com/DrDeer119/99.spec-kit-cross-platform-template)

---

## 1. 概述

本文件說明下游專案如何向上游範本（`99.spec-kit-cross-platform-template`）回饋改善建議、Bug 回報、功能提案等。

### 1.1 什麼是「上游貢獻」？

當你在使用 SpecKit + FlowKit 的過程中發現：
- 🐛 指令有 Bug 或行為不符預期
- 💡 有可通用化的改善想法
- 📝 文件缺失或不清楚
- 🔧 流程有可優化之處

這些都可以回饋到上游範本，讓所有下游專案受益。

---

## 2. 貢獻流程

### 2.1 提交 Issue（推薦）

**最簡單的貢獻方式**：在上游 Repo 提交 GitHub Issue。

```
https://github.com/DrDeer119/99.spec-kit-cross-platform-template/issues/new
```

### 2.2 Issue 撰寫規範 🔴 CRITICAL

> ⚠️ **Private Repo 注意事項**：上游範本維護者可能無法存取你的私人 Repo。  
> 因此 Issue 內容 **MUST 自包含**，不得僅引用私人 Repo 中的文件路徑。

**MUST 要求**：
- Issue 主體 MUST 包含完整的提案內容
- MUST NOT 僅以「請參考 `docs/xxx.md`」方式引用私人 Repo 文件
- 若有相關文件，MUST 將關鍵內容直接貼入 Issue 主體

**SHOULD 要求**：
- 使用 Issue Template（見§3）格式化內容
- 提供「問題描述」→「預期行為」→「建議方案」的完整脈絡
- 標註影響的指令名稱（如 `speckit.implement`、`flowkit.unify-flow`）

**允許（MAY）**：
- 引用公開 Repo 的文件連結
- 附上截圖或程式碼片段說明問題

### 2.3 提交 Pull Request

若你有完整的修改方案：

1. **Fork** 上游範本 Repo
2. 在 Fork 中建立 Feature Branch
3. 完成修改與測試
4. 提交 **Pull Request** 到上游 `main` 分支

## 4. Private Repo 特別指引

### 4.1 為什麼需要特別處理？

上游範本是 **Private Repo**（或可能是 Public），但下游專案通常也是 Private Repo。
範本維護者**無法看到**你的私人 Repo 中的文件。

❌ **錯誤示範**：
```markdown
詳細設計請參考 docs/02.規則研討/proposal-spec-status-lifecycle.md
```
→ 維護者看到 404 錯誤，無法審閱。

✅ **正確示範**：
```markdown
### 建議方案

Feature Spec 新增 Status 生命週期：

| 狀態 | 設定時機 | 設定者 |
|------|----------|--------|
| Draft | specify 建立時 | specify |
| In Progress | implement 開始時 | implement |
| Implemented | implement 完成後 | implement |
| Unified | unify-flow 封存前 | unify-flow |

需要修改的檔案：
1. `spec-template.md` — YAML 新增 status 欄位
2. `speckit.implement` — 新增 Step 1.6 + Step 11 Status 更新
3. `flowkit.unify-flow` — Phase 4 新增 Step 0
4. `constitution.md` — 新增 §1.5 生命週期定義
```

### 4.2 AI 協助流程

如果你的下游專案有 AI Agent，可以請 AI 協助準備 Issue：

> 「請根據我們的 `docs/xxx/proposal.md`，整理一份自包含的 GitHub Issue，  
>  目標是提交到上游範本 Repo。內容 MUST 完整，不要引用本地路徑。」

## 5. 版號同步確認

貢獻前，請先確認你的下游專案版號：

```powershell
# 查看當前版號
Get-Content ".flowkit\version-manifest.md" | Select-String "version"
```

在 Issue 中標註你使用的指令版本，有助於維護者判斷問題是否已在新版中修復。

## 6. 常見問題

### Q：我的改善只適用於我的專案，還需要提交嗎？

如果改善具有**通用性**（其他專案也可能受惠），建議提交。  
如果是**專案特化**（只對你的專案有意義），則不需要。

### Q：我提交了 Issue 但沒人回覆？

Private Repo 的通知可能不即時。建議：
1. 確認 Issue 格式完整
2. 在相關的溝通管道（如 Teams / Discord）提醒維護者

### Q：我可以直接修改上游範本嗎？

不建議。請透過 Issue 或 PR 的方式貢獻，讓維護者審閱後合併。
