# 跨範本同步變更流程

> **文件類型**：開發人員操作指南  
> **建立日期**：2026-02-10  
> **適用對象**：所有使用 SpecKit + FlowKit 架構的範本 Repo  
> **操作方式**：填寫下方參數區後，交由 AI Agent 執行

---

## 2. AI 讀取起點（給 AI Agent）

> AI Agent MUST 從本節開始讀取，並以 §3 的參數作為本次同步的輸入。

**實作經驗補充（重要）**：
- PR 若已存在，GitHub API 會回 422，AI MUST 改為「查詢既有 PR」並回報 URL。
- 目標 repo 若已有同名分支，分支名稱 MUST 加上時間戳或遞增尾碼。
- 若 `gh` 未登入，優先改用 GitHub REST API 建 PR（並記錄 token 來源）。

## 3. 目的

當**來源範本**（如 `99.spec-kit-cross-platform-template`）的 FlowKit / SpecKit 指令、模板或文件有更新時，需要將這些變更同步到其他同樣採用 SpecKit + FlowKit 的**目標範本**（如 `99.eletron-vite-speckit-flowkit`）。

本文件定義一套**可重複執行的同步流程**，AI Agent 只需閱讀本文件與下方參數，即可自動完成分支建立、patch 套用、推送與 PR 建立。

---

## 4. 同步參數（每次執行前填寫）

> AI Agent：請讀取此區塊作為本次同步的輸入參數。

```yaml
# ── 來源 ──
source_repo_path: "E:\\Dropbox\\80.Investment Research\\88.SKY888回測專案\\06.Victor\\09.Python\\99.spec-kit-cross-platform-template"
start_commit: "<起始 commit hash（含）>"
end_commit: "HEAD"               # 或指定結束 commit hash

# ── 目標 ──
target_repo_url: "https://github.com/DrDeer119/99.eletron-vite-speckit-flowkit.git"
target_base_branch: "main"       # PR 合併的目標分支

# ── 分支與 PR ──
sync_branch_prefix: "sync/"      # 分支前綴
pr_title_prefix: "sync:"         # PR 標題前綴
```

## 5. 執行流程

### 5.1 前置檢查

| 步驟 | 動作 | 說明 |
|------|------|------|
| 1 | 驗證來源 repo | 確認 `source_repo_path` 存在且為有效 Git repo |
| 2 | 驗證 commit 範圍 | `git log --oneline <start_commit>^..<end_commit>` 確認 commit 清單 |
| 3 | 列出變更檔案 | `git diff --stat <start_commit>^..<end_commit>` 確認影響範圍 |
| 4 | 確認無刪除衝突 | `git diff --diff-filter=D --name-only ...` 確認是否有刪除的檔案需特殊處理 |
| 5 | **版號清單比對** | 比對 `.flowkit/version-manifest.md`，確認同步範圍與版號差異 |

### 5.2 產生 Patch

```powershell
# 在來源 repo 目錄下執行
git format-patch <start_commit>^..<end_commit> -o "$env:TEMP\speckit-patches"
```

### 5.3 Clone 目標 Repo 並建分支

```powershell
# 使用暫存目錄（避免 Dropbox 同步干擾）
$tempPath = "$env:TEMP\speckit-sync-$(Get-Date -Format 'yyyyMMddHHmmss')"
git clone <target_repo_url> $tempPath

# 建新分支
cd $tempPath
$branchName = "<sync_branch_prefix>flowkit-speckit-updates-$(Get-Date -Format 'yyyyMMdd')"
git checkout -b $branchName
```

### 5.4 套用 Patch

```powershell
# 在目標 repo 目錄下逐一套用
Get-ChildItem "$env:TEMP\speckit-patches\*.patch" |
    Sort-Object Name |
    ForEach-Object {
        Write-Host "Applying: $($_.Name)"
        git am --3way $_.FullName
    }
```

**衝突處理**：
- 若 `git am` 失敗，先檢查衝突檔案
- 手動解決衝突後 `git am --continue`
- 若 patch 完全不適用，`git am --skip` 並記錄跳過原因

### 5.5 推送分支

```powershell
git push origin $branchName
```

### 5.6 建立 PR

```powershell
# 方式 A：GitHub CLI（推薦）
gh pr create \
    --base <target_base_branch> \
    --head $branchName \
    --title "<pr_title_prefix> FlowKit/SpecKit 同步更新 (from <source_repo> <start_commit>..<end_commit>)" \
    --body "<PR 內容，見下方模板>"

# 方式 B：GitHub REST API（gh 未安裝或未登入時）
# 從 git credential 取得 token，呼叫 POST /repos/{owner}/{repo}/pulls
# 若回 422，改用 GET /pulls?state=open&head=<owner>:<branch> 查詢已存在 PR
```

### 5.7 清理暫存

```powershell
# 刪除暫存目錄與 patch 檔案
Remove-Item -Recurse -Force $tempPath
Remove-Item -Recurse -Force "$env:TEMP\speckit-patches"
```

## 7. AI Agent 執行指引

當使用者要求同步變更時，AI Agent MUST 依照以下順序執行：

1. **讀取參數**：從本文件 §4 讀取 `source_repo_path`、`start_commit`、`end_commit`、`target_repo_url` 等參數
2. **前置檢查**：§5.1，確認 commit 範圍有效、列出變更清單
3. **向使用者確認**：顯示 commit 清單與變更檔案摘要，確認後再繼續
4. **產生 Patch**：§5.2
5. **Clone + 建分支**：§5.3（使用 `$env:TEMP` 避免 Dropbox 干擾）
6. **套用 Patch**：§5.4（逐一套用，遇衝突報告）
7. **推送**：§5.5
8. **建 PR**：§5.6（優先 `gh`，fallback GitHub REST API）
9. **清理**：§5.7
10. **回報結果**：PR URL、分支名稱、套用結果

**必回報欄位**：
- 同步 commit 範圍
- 分支名稱
- PR URL（若已存在，標記為「既有 PR」）
- 是否有衝突/跳過 patch
- 版號清單比對結果（同步前後 `.flowkit/version-manifest.md` 差異）

### 7.1 錯誤處理

| 情境 | 處理 |
|------|------|
| Patch 套用衝突 | 報告衝突檔案，嘗試 3-way merge；仍失敗則暫停等使用者決策 |
| Push 失敗（權限） | 確認認證方式，引導使用者登入 |
| 目標 repo 已有同名分支 | 在分支名稱加上時間戳區分 |
| `gh` 未安裝或未登入 | 使用 GitHub REST API 建 PR |
| PR 建立回 422 | 查詢既有 PR 並回報 URL |

## 8. 注意事項

1. **路徑相容性**：來源與目標 repo 的 `.cursor/`、`.github/`、`.flowkit/`、`docs/` 目錄結構 SHOULD 一致。若目標 repo 有不同的根目錄結構（如額外的 `src/electron/`），patch 仍可套用，但可能需要手動調整。
2. **Merge Commit**：`git format-patch` 預設會展開 merge commit 為個別 commit 的 patch。若來源範圍內含 merge commit，產出的 patch 數量可能與 commit 數不同。
3. **暫存目錄**：MUST 使用 `$env:TEMP` 而非 Dropbox/雲端同步目錄，避免同步鎖定問題。
4. **認證**：首次使用需確保 `gh auth login` 或 Git credential manager 已設定完成。
5. **重跑同步**：若需重做同一範圍，建議改用新分支名稱，避免與已存在 PR/分支衝突。
6. **暫存清理**：若 PowerShell 中斷，暫存目錄可能殘留，建議手動刪除 `$env:TEMP\speckit-*`。
