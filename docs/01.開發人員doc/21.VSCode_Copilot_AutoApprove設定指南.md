# VS Code Copilot Agent AutoApprove 設定指南

> **適用版本**：VS Code + GitHub Copilot Chat（Agent 模式）  
> **最後更新**：2026-03-04  
> **設定檔位置**：  
> - 全域：`%APPDATA%\Code\User\settings.json`（Windows）  
> - 專案：`.vscode/settings.json`（已內建於本範本）

---

## 重要：User Settings vs Workspace Settings

VS Code 設定有三個層級，優先序為：**Workspace > User > Default**

`chat.tools.terminal.autoApprove` 若在 **Workspace 層級**（`.vscode/settings.json`）有任何設定，會**完整覆蓋** User 層級的設定。

**解決方法**：兩個檔案必須同步保持相同設定：
- `%APPDATA%\Code\User\settings.json`（全域）
- `.vscode/settings.json`（專案，已內建，無需重複建立）

---

## 一次性啟用步驟（新環境必做）

VS Code 強制要求使用者**親自確認一次**「Enable Auto Approve 警告」，這個紀錄存在本機 Storage 裡（非 settings.json）。沒有接受過，即使設定正確也不會自動放行。

**步驟（每台機器只需做一次）：**
1. 讓 AI 執行任意指令，出現詢問視窗時
2. 點 **「Allow」旁邊的下拉箭頭**
3. 選 **「Enable Auto Approve...」**
4. 在警告對話框點 **「Enable」**

完成後，所有符合規則的指令就會永久自動放行（直到清除 VS Code 本機 Storage）。

## 完整設定區塊

> 本範本的 `.vscode/settings.json` 已內建以下設定。  
> 新機器只需在 **User Settings** 同步一份（見下方步驟）。

```jsonc
// 終端機：啟用 auto approve 功能
"chat.tools.terminal.enableAutoApprove": true,

// 終端機指令自動放行規則
"chat.tools.terminal.autoApprove": {
    // 預設全開：/.*/  是正確的 catch-all regex
    // 注意："*" 是字面字串（只匹配開頭為 * 的指令），不是萬用字元
    "/.*/": true,

    // 永遠不要自動放行（false 優先權高於 /.*/）
    "del": false,
    "rm": false,
    "rmdir": false,
    "/^Remove-Item\\b/i": false,
    "/^git (clean|reset.*--hard|rm)/i": false
},

// 網站 URL 自動放行（全開）
"chat.tools.urls.autoApprove": {
    "*": true
},

// Agent 最大自動請求次數（避免無限迴圈）
"chat.agent.maxRequests": 100,

// Git 確認同步：關閉（讓 AI 自由 push/pull）
"git.confirmSync": false,

// Git 自動 fetch
"git.autofetch": true
```

---

## 規則說明

### `chat.tools.terminal.autoApprove`

| 鍵（Key） | 型態 | 說明 |
|-----------|------|------|
| `"/.*/"`  | Regex catch-all | 比對所有指令字串（真正的萬用字元） |
| `"/pattern/flags"` | Regex | 以正則表達式比對，`i` 代表不分大小寫 |
| `"literal"` | 字面字串 | 比對指令**開頭**是否符合此字串 |
| 值 `true` | Boolean | 自動放行，不跳出確認對話框 |
| 值 `false` | Boolean | 強制要求人工確認，優先權高於 `"/.*/": true` |

> **優先順序**：明確的 `false` 規則永遠高於 `"/.*/": true`。

### 為什麼用 `"/.*/": true` 而不是 `"*": true`？

在 `chat.tools.terminal.autoApprove` 中，每個 key 是**指令前綴比對**（字面字串）或 **Regex**（用 `/` 包裹）。  
`"*"` 只是字面字串，只會比對開頭為 `*` 的指令，無法作為萬用字元。  
`"/.*/": true` 才是正確的 Regex，能比對任何非空指令字串。

### `chat.tools.urls.autoApprove`

URL autoApprove 使用不同的比對機制，`"*": true` 在這裡**確實**代表全開。

---

## 封鎖的危險指令

以下指令即使設定了 `"/.*/": true`，仍強制要求人工確認：

| 指令 | 說明 |
|------|------|
| `del` | CMD 刪除檔案 |
| `rm` | Unix-style 刪除（WSL、Git Bash） |
| `rmdir` | 刪除目錄 |
| `/^Remove-Item\b/i` | PowerShell 刪除指令（不分大小寫） |
| `/^git (clean\|reset.*--hard\|rm)/i` | 危險 git 指令 |

## 如何修改設定

### User 層級（全域，新機器必做）
1. `Ctrl+Shift+P` → `Open User Settings (JSON)` → Enter
2. 貼上上方「完整設定區塊」中的全部內容
3. 儲存後立即生效

### Workspace 層級（專案）
- 本範本的 `.vscode/settings.json` 已內建，**無需手動建立**
- 若需新增封鎖指令，直接編輯 `.vscode/settings.json` 並同步更新 User Settings

## 常見問題

**Q：設定都正確了，還是有詢問視窗？**  
A：需要完成一次性「Enable Auto Approve」啟用步驟（見上方）。這個確認紀錄存在 VS Code 本機 Storage 裡，不在 settings.json，需要手動透過 UI 確認一次。

**Q：User settings 已設定，重啟 VS Code 後某些指令還是會詢問？**  
A：檢查專案的 `.vscode/settings.json` 是否有 `chat.tools.terminal.autoApprove` 區塊。Workspace 設定會完整覆蓋 User 設定，必須同步更新兩個檔案。

**Q：`.ps1` 腳本需要特別設定嗎？**  
A：不需要。`"/.*/": true` 已涵蓋所有指令。

**Q：想新增一個永久封鎖的指令？**  
A：在 `autoApprove` 區塊加入 `"指令前綴": false`，並同步更新 `.vscode/settings.json` 與 User Settings。
