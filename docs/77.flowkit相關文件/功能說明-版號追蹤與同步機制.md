# 版號追蹤與同步機制

> **版本**：v1.1.0  
> **最後更新**：2026-02-25  
> **適用對象**：範本維護者、下游專案開發人員、AI Agent  
> **相關檔案**：`.flowkit/version-manifest.md`

---

## 1. 功能概述

### 1.1 這是什麼？

**版號追蹤與同步機制**是一套輕量化的版本管理方案，透過 `.flowkit/version-manifest.md` 作為版號清單（Version Manifest），讓下游專案或其他範本能在同步更新後，**快速比對版號差異**，識別哪些指令化檔案已落後、哪些已是最新。

### 1.2 解決什麼問題？

| 問題 | 解決方式 |
|------|----------|
| 改版太快，下游不知版號差異 | Manifest 集中記錄所有指令版號 |
| 同步後無法確認是否完整 | 可用 `code --diff` 快速比對兩邊 Manifest |
| Git commit 難以追溯哪版改了什麼 | 每個版號對應 Git Commit Hash |
| 跨範本同步缺乏驗證機制 | 同步流程加入 Manifest 比對步驟 |
| 遷移腳本無法確認更新範圍 | 遷移後自動複製 Manifest 供比對 |

### 1.3 核心價值

```
「一份清單掌握全部版號，一次比對看完所有差異。」
```

## 2. Manifest 檔案規格

### 2.1 檔案位置

```
.flowkit/version-manifest.md
```

### 2.2 結構

| 區段 | 內容 | 說明 |
|------|------|------|
| **FlowKit 指令版號** | 12 個 FlowKit 指令 | 版本、日期、commit |
| **SpecKit 指令版號** | 9 個 SpecKit 指令 | 版本、日期、commit |
| **範本與規範版號** | constitution、template 等 | 版本、日期、commit |

### 2.3 欄位說明

| 欄位 | 說明 | 範例 |
|------|------|------|
| 指令 | 完整指令名稱 | `flowkit.code-check` |
| 版本 | SemVer 格式 | `1.8.0` |
| 最後更新 | ISO 日期 | `2026-02-16` |
| 對應 Commit | Git short hash（7 碼），屬於**本 Manifest 所在範本 Repo** | `ceb4710` |
| 說明 | 一句話功能摘要 | AI 五層驗證金字塔 |

### 2.4 來源範本識別

Manifest 的標頭區塊包含 `來源範本` 與 `Repo` 欄位，標明所有 Commit Hash 所屬的 Repo：

```markdown
> **來源範本**：`99.spec-kit-cross-platform-template`（通用跨平台版）
> **Repo**：`https://github.com/DrDeer119/99.spec-kit-cross-platform-template.git`
```

> ⚠️ **多範本環境**：目前存在兩個範本 Repo（通用跨平台版 vs Electron Vite 版），
> 各自維護獨立的 Manifest。跨範本同步時，以**版號（SemVer）**為主要比對依據，
> Commit Hash 僅用於追溯該範本 Repo 內的變更。

## 3. 更新規則

### 3.1 何時更新 Manifest

| 觸發事件 | MUST/SHOULD | 說明 |
|----------|-------------|------|
| 修改 Agent / Command 檔案 | **MUST** | 版號變更必須同步更新 Manifest |
| 修改 Constitution / Template | **MUST** | 規範變更必須記錄 |
| 修改功能說明文件 | SHOULD | 文件更新可選記錄 |
| 僅修改 docs/ 非指令化文件 | MAY | 視情況 |

### 3.2 誰負責更新

- **跨範本同步**：同步完成後，AI Agent 或人工 MUST 更新 Manifest
- **遷移腳本**：`migrate-to-full-kit.ps1` 執行時自動複製 Manifest
- **日常改版**：修改 Agent/Command 的 commit 中 SHOULD 一併更新 Manifest

### 3.3 Commit 規範

更新 Manifest 時，SHOULD 在 commit message 中標註：

```
chore: 更新 version-manifest（code-check 1.8.0, refine-loop 1.5.0）
```

或合併在功能 commit 中：

```
feat(code-check): 非功能回歸分流 + xdist fallback

同步更新 version-manifest
```

## 4. 使用情境

### 4.1 跨範本同步

在執行 `docs/01.開發人員doc/05.跨範本同步變更流程.md` 的同步流程時：

**同步前**：
```powershell
# 比對版號差異
code --diff "$sourcePath\.flowkit\version-manifest.md" `
            "$targetPath\.flowkit\version-manifest.md"
```

**同步後**：
```powershell
# 驗證版號已對齊
$source = Get-Content "$sourcePath\.flowkit\version-manifest.md"
$target = Get-Content "$targetPath\.flowkit\version-manifest.md"
if (Compare-Object $source $target) {
    Write-Host "⚠️ 版號清單仍有差異，請確認是否為預期的專案特化"
} else {
    Write-Host "✅ 版號清單完全一致"
}
```

### 4.2 專案遷移（migrate-to-full-kit）

遷移腳本執行時：
1. 自動複製 `.flowkit/version-manifest.md` 到目標專案
2. 遷移完成後，使用者可比對版號確認遷移完整性

### 4.3 下游專案日常維護

下游專案開發人員可定期比對：

```powershell
# 1. 取得上游最新 Manifest
git clone https://github.com/DrDeer119/99.spec-kit-cross-platform-template.git $env:TEMP\upstream-check
# 2. 比對
code --diff "$env:TEMP\upstream-check\.flowkit\version-manifest.md" `
            ".\.flowkit\version-manifest.md"
# 3. 清理
Remove-Item -Recurse -Force "$env:TEMP\upstream-check"
```

### 4.4 AI Agent 自動檢查

AI Agent 在執行指令前，MAY 讀取 Manifest 確認版號一致性：

```
讀取 .flowkit/version-manifest.md
→ 比對當前執行的 Agent 版號
→ 若不一致 → 警告使用者可能需要更新
```

## 6. 常見問題

### Q：Manifest 和改版歷史有什麼不同？

| 面向 | version-manifest.md | flowkit-version-history.md |
|------|---------------------|---------------------------|
| 目的 | 快速比對當前版號 | 記錄所有歷史變更 |
| 內容 | 僅當前版號 + commit | 所有版本的變更說明 |
| 使用場景 | 同步/遷移後驗證 | 瞭解某版本改了什麼 |
| 更新頻率 | 每次 Agent 變更 | 每次 Agent 變更 |

### Q：SpecKit 原版指令沒有版號怎麼辦？

以 `1.0.0` 為基線。自定義版本加入的功能（如 implement 的 Status 自動管理、specify 的 Milestone 偵測等）以 `1.1.0` 起標記。

### Q：如果下游專案有自己的客製化版本怎辦？

下游專案可在 Manifest 中加入備註欄：

```markdown
| `flowkit.code-check` | 1.8.0 | ... | ✅ 同步 | — |
| `speckit.implement` | 1.2.0-local | ... | 🔧 本地客製 | 加入專案特化邏輯 |
```

### Q：兩個範本 Repo 的 Commit Hash 會衝突嗎？

不會衝突。每個 Manifest 標頭的 `來源範本` 與 `Repo` 欄位已明確標示所有 Commit Hash 所屬的 Repo。跨範本同步時，以**版號（SemVer）**為主要比對依據，Commit Hash 僅用於追溯對應範本 Repo 內的變更歷史。
